# 独立审查（2026-09-21）：268 个绿灯底下有什么

六路独立审查（LP/极限分析、三维几何、理论-代码一致性、二维与读取器、门的牙、声称对照代码），
**每条发现都被另一路用代码实际复现或推翻**，最后一路专门回答"什么没审到"。
40 个智能体、413 次工具调用、25 分钟。

**35 条原始发现 → 去重 33 → 31 条确认、2 条推翻、0 条存疑；另有 6 处审查盲区。**
确认的 31 条里：**2 条 critical、15 条 major、14 条 minor。**

先说结论：**过去三天写的代码里有真正给出错误数值的缺陷，268 个测试一条都没抓到；
README 与报告里有四条声称是假的；两条地基性的结论（二维凹几何 G0、首入）缺乏支撑。**
L3 极限分析与 L5 逃逸剖面那次跨层交叉验证仍然成立——它之所以成立，恰恰是因为两条路径零共用代码。
这次审查最大的教训就在这句话里。

## 为什么 268 个绿灯没抓到

审查把原因看得很清楚，三条都是结构性的：

1. **参数化恰好避开了失败格子。** 极限分析的 Patton 门只测了 (amp, μ) 六组，而 (0.2, 0.1)、(0.3, 0.1) 会静默返回 `infeasible`；
   裕度层的可微路径只在一个手选偏移上测，而 `body_distance` 在一般位置下有 51% 的概率返回该路径不支持的标签；
   逃逸高度只在 nx=4 的对称块上测，换 nx=5 就 10/25 错。
2. **oracle 与被测代码共用同一段几何原语。** `point_in_polyhedron`（射线奇偶）与"暴力"谓词都用从 f[0] 出发的扇形三角化，
   非凸面上两者一起错；`_point_inside_face` 与 `_point_face_distance` 都用半平面核（只对凸面正确）；
   二维 bb52 的"凹几何 G0"用 sign(min gap) 当 oracle——**正是我在三维上亲手证伪过的那条规则**。
3. **声称先于门写进了文档。** "三维 G0 三票"实际只实现两票；"首入"三维没有实现；"随 k 单调收敛"不单调；
   "贯入之后见证距离恒为 0"是假的——贯入时 `body_distance` 返回一个**正的**假距离，裕度谓词回答"安全"。

## 确认的缺陷（按严重度）

### Critical

**C1 · `lp.py:100` + `limit.py:171` — 可行问题被静默判成不可行。**
一阶段可行性用绝对阈值 `-T[m][-1] > tol`，而 `limit_load` 把 tol 再乘 1e-3 变成 1e-12；
b = −W_dead 量级 100 时，一阶段收敛后人工变量和的舍入残差 ~2e-12，于是返回 `status='infeasible', alpha=nan`。
实测：`interlocking_pair(4,2,0.2)`、μ=0.1、默认 k=8 → infeasible（真值 52.083）；
(0.25,0.2) 在 k = 6/7/8/19/20/32 上 optimal/infeasible 交替；测试自己的 k=16 下 (0.2,0.1)、(0.3,0.1) 都 infeasible。
**测试套件是靠参数化恰好避开这些格子才绿的。** 相对阈值（tol × max(1, max b)）或行归一化后三例全部 optimal 且等于 Patton 解析值。

**C2 · `covers3.py:446` — 凸成员谓词丢掉全部退化 facet，给出错误判定并会崩溃。**
`membership_convex3` 只用 `strict=True` 的 facet 取 max。凡是 B 的面法向恰与 A 的某面反平行、或与对方棱平行的 facet 都非严格，被整个丢掉。
实测：四面体 vs 单位方块，平移 x=(t,0,0) 在 t ≥ 1.0 时全部判"相交"（t=1.5/2/3 明明分离 ≥ 0.5）；
`g0_convex3(tetra, box)` 报 57/200 失配；两个轴对齐方块直接崩溃（空集取 max）。
随机凸包处于一般位置所以没有退化 facet，G0 门因此一直绿。
修法：成员谓词改用 E = B ⊕ (−A) 的**全部支撑半空间**（对 B 每个面法向 n 取 A 上 n·a 最小的顶点，反之亦然），与严格性无关。

### Major

**M1 · `limit.py:239` — `check_duality` 在有黏聚力时全错。** 两个独立原因：列表只由摩擦锥棱重建而 `res.lambdas` 里黏聚列交错其间，下标错位（复现出 0.3333 的假互补违约）；对偶解里黏聚约束行的乘子被 zip 截断，上限漏掉 Σy_row，对偶间隙恰等于黏聚贡献（复现 6.0）。测试从未在有黏聚力时调 `check_duality`。修法：把列构造抽成 `_build_columns` 三处共用。

**M2 · `covers3.py:223` + `geom3.py:475` — 点在面内的判定用的是半平面核，不是多边形内部。** 对有反射顶点的面（L 块顶底面、`merge_coplanar` 归并出的十边形侧面），投影落在"臂"里的顶点被判 `in_extent=False`，VF/FV 盖被丢，`brute_feature_distance` 退化到顶点/棱对而高估距离。修法：统一一个 `point_in_face_polygon`（投影到主轴平面 + 环绕数），三处共用。

**M3 · `g03.py:50` — "三维 G0 三票"实际只有两票。** `local_facets3` 被算出来但从未与 conv{b−a} 的 facet 集比较；`passed` 不看 facet。删掉任一严格 facet，181/190 次仍 passed。文档与 `reports/phase2_3d_kernel.md:16` 的声称是假的。

**M4 · `geom3.py:394` — 扇形三角化只对凸面正确。** `_point_on_face`、`segment_crosses_face`、射线奇偶三处都从 f[0] 扇出并接受任一三角命中，非凸面上三角溢出多边形。实测：细杆 vs L 块分离却报 1；点被判"边界"。与 M2 同一个修法。

**M5 · `geom3.py:449` — 暴力相交谓词仍会漏判正体积交集。** 每个顶点都落在对方面平面上、且无棱穿面内部时（L 块凹槽里咬进 ~0.05 的方块），前三步证人全空，兜底网格采样的是 AABB 交集（2×2×1）而非真交集（0.003×2×1），返回 0（相触）而真值是 1（体积 0.012）。修法：对每个"相触"顶点沿内法向和微推做证人。

**M6 · `geom3.py:632` — `merge_coplanar` 没有邻接判定。** 只按支撑平面分组：两个共面面只在一个顶点相触（pinch）时 `boundary[a]=b` 字典静默覆盖、`while cur != start` **死循环**；两个共面但不共棱的面（U 形棱柱两个端面）被强行归并后抛 ValueError。两种都是合法闭流形。修法：平面组内按共棱做并查集连通分量再归并。

**M7 · `interlock.py:92` — 逃逸候选集不完备，文档撒谎。** docstring 说"不施加 in_extent 过滤"，代码却用 `enumerate_covers3` 的默认 `require_in_extent=True`。默认块（nx=4，对称）上 0/25 错，`interlocking_pair(5,2,0.3)` 上 **10/25 随机偏移错**（0.44749 vs 真值 0.40054，静默偏大）。

**M8 · `margin.py:46` / `:118` — 裕度层贯入时给出"安全"，是 fail-unsafe。** `body_distance` 与 `margin_contacts` 没有 overlap 守卫；贯入时 |point_a − point_b| 是贯入深度（正数），`margin_contacts(delta=0.1)` 返回 []（"无广义接触闭合"），而同一输入 `inflated_membership` 答 INSIDE。模块文档与 `reports/margin_layer.md:81` 说的"贯入之后见证距离恒为 0"是假的。修法：入口处 `polyhedra_overlap==1` 则返回哨兵接触（margin_gap = −δ、closed=True）或抛错。

**M9 · `margin.py:175` + `frozen.py` — 可微裕度路径对约一半分离位形崩溃。** `body_distance` 在一般位置下 51% 返回 VE3/EV3 标签（400 样本：134 + 63），而 `frozen_normal`/`frozen_gap` 只支持 VF/FV/EE/VV3，直接 raise。测试 `assert lab[0] in (...)` 把缺失分支当前置条件。补两个泛型分支（顶点到棱直线的投影残差）后 400 样本零崩溃、maxerr 8.9e-16。

**M10 · `tools/g2_bdda3d.py:83` — G2 门对棱-棱接触结构性失明。** legacy 非 np 入口进 UNSUPPORTED 桶却不导致失败；内核 EE/VE3/EV3/VV3 盖进 detail 桶不参与对账。实测：伪造一条 `ee` legacy 入口 → 门绿；注入一个多余的内核 EE 盖 → 门绿。修法：UNSUPPORTED 非空即红；`n_covers == len(mine)` 否则红。

**M11 · `tools/tia_sensitivity.py:62` — 在不可微点报出一个导数。** 默认剖面 phase=0 处 h 关于 phase 是偶函数（h(δ,+φ)=h(δ,−φ)>h(δ,0)，已对暴力二分核实），∂h/∂phase 不存在；报出的 +0.5δ 是 float 路径恰好选中的那个并列盖的**单侧**方向导数，选左邻会得到另一个标签。tan_psi 在盖切换点（δ=0.5）同理。修法：冻结后在 ±ε 重定盖标签，标签变化或单侧差商不一致即标记 `differentiable=False`。

（M12–M15 为上述条目的重复报告，已合并计数。）

### Minor（14 条，逐条见 `reports/audit_20260921.json`）

要点：三维内接锥"随 k 单调收敛"**不成立**（k 为 4 的倍数时棱恰落在滑动方向所以精确，其余 k 振荡；门里 k=6 被 `if k>=8` 豁免，"converges"从未被检验）；
`contacts_from_covers` 取见证段中点当接触点，gap>0 时力的作用线偏移 gap/2，倾覆算例 3.1746 vs 真值 3.3333（应取 `point_a`）；
`test_lp` 在 UNBOUNDED 时静默 return，**7/12 个种子走这条路**，"对枚举全部基本可行解（12 组）"实际只有 5 组；
`Dual.__float__` 让 `math.sin(Dual)` 静默降为 float，而 `osteomorphic_block_generic` 默认 `sin_fn=math.sin`——不传 `sin_fn=D.sin` 时 ∂h/∂phase 从 0.23 静默变 0，primal 逐位不变，任何值门抓不到；
`atan2` 两个 Dual 宽度不同时静默截断；`__pow__` 负底非整数幂返回复数；
二维 `normal_cone` 遇连续重复顶点抛 ZeroDivisionError，读取器只剥尾部回绕点不剥内部重复；
`ve3_cover`/`ev3_cover` 把 `strict` 写死为 True，低维盖的 strict 过滤是死代码；
`escape_height_covers(verify=False)` 返回的正是文档判定无效的纯盖规则（δ=0.4 → 0.300 vs 0.200），无测试无警告；
`test_inflated_normal_is_lipschitz` **无牙**：样本点对间距 0.42 ≫ δ，任何单位向量函数的商都 ≤ 4.81 < 8，随机向量/常向量/局部反号四种错误实现全过；
`test_readers_roundtrip` 的 `len(keys)==len(records)` 是同义反复，且 `canonical_key` 对 bdda3d 不单射（面下标硬编码 −1）；
`polyhedron_preserving_indices` 未被任何面引用的输入顶点静默保留。

## 推翻的 2 条

- `bdda_df.py:156` VV 接触的 feature_b 标成 'edge'：复现者用 verts.csv 实测了三个真实案例，legacy 的 v-v 行本身就是"顶点对边 (p2,p3) + 第二参考对边 (m5,m6)"的组合，真正配对的顶点是两条边的公共端点（三例里两次是 p3 一次是 p2，p2 距 p1 可达 1.4）。**把 p2 标成 edge 是忠实转写**，改成 vertex 反而 3 例错 2。
- `tf_probe.py:76` 探针 contact_type 被当入口类：`CoverType.NN/NE` 自带"候选类（入口展开前）"语义，raw 码保留，1420 行全是 2（n-p），两种读法下都是 VF；area=1.0 的占位性质台账已写明。数字复现但无一是错值。

## 六处审查盲区（比缺陷更要紧）

1. **二维凹几何 G0 "1186/1186" 建在已证伪的规则上。** `tools/bb52_g0.py:135` 用 sign(min gap) 判相交——正是三维上实测被推翻的那条。批评者构造了细臂 L 块 + 凹槽内悬浮方块：`polygons_overlap` 说分离，投票说相交。README "L1 二维 ✔" 的凹块部分**目前无支撑**，必须换成暴力 `polygons_overlap` 重跑。
2. **首入（命题 7）三维零实现。** grep `first_entrance|首入` 在 kernel3d 下无结果，而 `reports/phase2_3d_kernel.md:13` 与 README L1 都把"首入"列为已交付。首入恰恰是 DDA 真正消费的那条规则（集值点上谁定接触点与法向）。二维实现对凹块分离情形也承认不对。
3. **G2 的 legacy 侧未被哈希看护。** `fixtures/PROVENANCE.json` 里 bdda3d 条目为 0，三个 JSON 若被编辑或换版本重导，"零差异"会静默失效。
4. **没有做过"正本对代码"的核对。** `D:\E(A, B)\01 精细版` 的命题 4 明写四类盖清单只在**一般位置**下成立——这次的方块崩溃与四面体误判正是退化情形；自创的"定理"（裕度层四条）也没人对照过正本编号。
5. **tf.cpp 读取器路径从未被执行攻击。** TF_MODE 把状态 4/5/6 折进 SLIDING/LOCKED 无验证。
6. **没有任何跨层端到端路径被测过。** `limit_load` 从未跑过 cb2_sliding/cb2_locked 夹具（名字里带着免费的力学判决）；接缝处（非零窗口的 `contacts_from_covers`、裕度→极限、夹具几何→盖→LP）正是这次发现静默错值的地方。

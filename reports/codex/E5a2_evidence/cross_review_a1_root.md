## 2. A1 算法审阅

### 一般闭表面重叠

- convex SAT 快路先要求给定表面的每个三角平面均包含所有原顶点；在已声明的有效朝外闭合嵌入表面前提下，这证明源实体本身凸，不是默默把凹体换成凸包。
- 一般路径将每片三角形按另一表面全部三角平面切分；同平面三角形还加入各边对应的切线平面。这避免漏掉共面部分重合区域，开二维 cell 上另一实体的成员状态不会越过未切开的真实边界。
- 凸 cell 的顶点均值在相对内部；沿本面内向法线取全部正平面截距的一半，给出确切有理内部点，不是固定 epsilon 或有限探针碰运气。最后又检查见证确实严格位于两个实体内部。
- 有界、非空体积交集必有一侧输入表面贡献的开边界片。该片或在另一实体内部，或与另一边界共面且内侧一致；两分支因此覆盖一般有效闭表面的内部重叠情形。仅共同棱/点接触没有三维内部，不被升格为贯入。

### 内部折棱与 segment

- 单个三角边上的命中不能直接当作源折面横穿。新增逻辑以线段与全部面平面的精确参数切点划分邻域，左右分别取相邻参数中点，再要求实体状态一个内部一个外部。
- 源 face-ring 的真正边界仍由精确点段距排除；共面线段不会作为横穿返回。正 tol 的额外条件没有重新引入舍入地板。
- 已有解析屋脊 `z=1-|x+y|/2` 门同时区分沿屋脊切触与竖直横穿，并用真实内部分支变异看护。这个闭式门不依赖 tetrahedral oracle 的三角化结论。

### 补充小检查

未启动额外长测试。只运行一个约 0.18 秒的原生 Python 检查：非星形 U 棱柱，截面
`(0,0),(3,0),(3,3),(2,3),(2,1),(1,1),(1,3),(0,3)`，高度 `[0,1]`。
独立真值来自三个轴对齐长方体的并集，不调用任何生产谓词作为 oracle。结果：

- U 与自身：严格重叠 1；
- 槽内方块：分离 -1；
- 左壁恰相触：0；
- 左壁侵入 `2^-70`：1。

实际结果全部与上述闭式真值一致。这个补充检查不是普遍正确性证明，也没有替代现有门。

## 3. Oracle 独立性及不能扩大声称的边界

`e5a2_surface_oracle.py` 未导入生产几何/谓词/三角化代码；其重叠算法是严格核验星形内核点之后，将实体分成径向四面体并用整数 SAT，区别于生产一般 arrangement/奇偶成员法。`star_relation` 另外用本文件的有理特征距离检查分离侧报告带。

需准确理解其独立性：

- 它是**星形**源表面的 oracle，不适用于任意非星形闭表面；代码对找不到严格核点明确断言失败，没有回退成凸包。本次 root 的 `stack_touch` 应用在这个范围内。
- 非平面 face-ring 需要按同一确定性 ear 规则定义同一个实体，oracle 自行实现该规则，但控制结构与生产 ear clipping 很接近。因此它可以独立验证重叠算法，不能单凭这一对拍宣称已经独立审查所有三角化实现错误。现有 L 并集、解析屋脊及本次 U 并集检查提供不同来源的覆盖；完整任意三角化审查仍属于后续正式 G6 的范围。
- 浮点刚体变换后的真实微折面和微贯入不能继续以理想位形标签盖过；root 改写在原输入上核验，没有替换原顶点。

未发现隐蔽的生产函数复用；也未将同算法双实现的覆盖范围夸大为一般全域 oracle。

## 4. Minor 已关闭：开口 face-only 的 segment 契约

复现：单独一片正方形 `z=0`（没有闭合实体），竖线在其三角化对角线中心穿过时返回 False，离开该对角线则 True。原因是内部折棱分支需要全实体两侧成员，开口对象没有该语义。

root 已补 public docstring：`P must be a valid outward-oriented closed embedded surface, not a single open face`，明确开口 face-only 不在契约。本审查已读回确认。逻辑没有为此改动，minor 关闭。

- 标签差异仍是工单要求的严格输出合同未满足项；**不能因数值相同而自行吞掉标签差异或宣称 L4 全绿**。

## 原因与可行处理边界

这部分输出当前是**基依赖的证书分量标签**：Python `critical.improving_basis2` 先按归一化改进射线正支撑排序，再贪心保留独立接触列；射线/最优基本来不唯一。Python `lp.solve` 先尝试浮点单纯形候选并在有理层核证，候选通过即返回；C++ 的独立求解路径可以得到不同但同样合法的射线。后续 `sensitivity._threshold_sensitivity2` 正确地逐一保留所选分支的全部越零分量标签。因此“两个合法基得同一阈值及斜率”并不推出“两个基的越零分量标签集合相同”。

在不更改 Python 数学合同、不让 C++ 消费 Python 结果、不复制 Python 求解器择基/平局路径的前提下，**现有定义未提供可推导出当前 Python 那一特定标签子集的独立规范化规则**。可能的处理均需所有者明确决定，当前代理不实施：

1. 若继续要求输出逐集合相等，需要明订共同的、与后端无关的规范临界基或物理标签定义，并由双方遵守；不能只在 C++ 硬编码本 16 点。
2. 若承认 tied_labels 在此类隐函数结果中属于基依赖证书的一部分，可讨论按原始几何逐分量核验并保留双侧标签差异的比较合同；但这会变更工单当前要求，不能由执行者自行放宽。
3. 未获得决定时，严格保留 32 项 RED，报告为未完成合同项；其余数值/证明能力验证结果仍按实际记录，不连带否定，也不升级成完整通过。

本取证没有证明任意输入域的唯一标签规范化，也不宣称对抗核查完成。

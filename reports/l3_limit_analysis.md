## 结构：静力下限与运动上限由同一次求解同时给出

下限定理（静力）写成线性规划：

```
max α   s.t.   Σ_ij λ_ij w_ij + W_dead + α·W_live = 0 ,  λ ≥ 0
```

w_ij 是第 i 个接触第 j 条摩擦锥棱的旋量。而这个 LP 的**对偶解就是破坏机构**：
对偶可行性 yᵀw ≥ 0 正是"虚速度场不得贯入任何接触"，强对偶 α* = −yᵀW_dead 就是
上限定理的功率平衡。**所以这一层自带校验：下限必须等于上限，不等就是错。**

> **订正（2026-09-24）：上面的强对偶式只对纯摩擦成立。** 有黏聚力时，LP 为每个黏聚接触多一行
> Σλ_coh + s = 1（右端为 1，见文末"坑 3"），这些行也有对偶乘子 y_r，强对偶应写成
>
> ```
> α* = −y_wᵀ W_dead + Σ_r y_r
> ```
>
> y_w 是旋量行的乘子（即机构，`LimitResult.mechanism`，恰为 3 或 6 个分量），y_r 是黏聚行的乘子
> （`LimitResult.row_duals`），力学含义是黏聚力在机构上的耗散功率。M0 之前 `check_duality` 漏掉 Σy_r，
> 且黏聚列的下标与重建的摩擦列错位，所以**带黏聚力时这道自校验本身是无效的**：会报出恰等于 2cA 的假对偶间隙
> 和假互补违约（审查 M1 复现出 6.0 与 0.3333）。现在三处共用 `_build_columns`，门见下表"对偶"一行。
> 手算对偶的佐证：`tests/test_limit_duality.py::test_pure_cohesion_mechanism_and_row_duals_match_the_hand_solved_dual`
> （机构 (1,0,0)、两条黏聚行乘子各 = cA = 3、bᵀy 手写等于 α）。

与盖系统的接口在这里咬合：约束 yᵀw ≥ 0 的那组法向，正是盖枚举输出的**完备清单**。
"机构不得进入入口块"就是这里的运动学容许条件——L1 与 L3 不是并列的两层，是同一件事的两面。

## 经典算例：滑动 vs 倾覆

宽 2、高 3、自重 10 的方块放在地面，水平力作用在顶部。解析解 α* = min(μW, Ww/(2h))，
分界在 μ = w/(2h) = 1/3。

九个摩擦系数逐点吻合到 1e-9，**而且破坏模式是从对偶解读出来的**：

- μ < 1/3：机构 ω = 0（平动），两个角都受力；而且 v_y = μ·v_x——**关联流动，剪胀角等于摩擦角**
- μ > 1/3：机构 ω ≠ 0，右趾速度恰为零（绕趾转动），活动接触只剩右趾

## 三个自己踩的坑

1. **对偶行的符号。** `solve` 里为让 b ≥ 0 把部分行取负，返回的 y 就对应取负后的系统，
   与调用方手里的 A、b 差一个符号——12 组强对偶测试红了 7 组。取负的行其乘子要翻回来。
2. **机构容许性的不等号方向写反。** 正确是 yᵀw **≥ 0**（正 = 分离）。写成 ≤ 0 时
   全部算例误报不容许，而 α 值却是对的——**门和被测对象错得不一样，所以能抓住**。
3. **黏聚力写成了无界非负射线**，于是可以无限放大，LP 直接报无界。黏聚抗剪是**有界**的
   （|F_s| ≤ cA，与法向压力无关），必须为每个黏聚接触补一行 Σλ + s = 1。

## 诚实边界

- **二维摩擦锥线性化是精确的**（锥恰有两条极棱）；**三维是 k 边内接棱锥**，
  内接 ⇒ 容许集变小 ⇒ 承载力**偏安全**，~~偏差量级 1 − cos(π/k)。已钉成收敛门。~~
  **订正（2026-09-24）**：内接棱锥 ⊇ 摩擦系数 μ·cos(π/k) 的精确圆锥（正 k 边形的内切圆半径是外接圆的 cos(π/k) 倍），
  所以承载力夹在这两个锥的解之间；纯滑动时相对短缺 ≤ 1 − cos(π/k)，荷载恰好平分两条棱时取到（扁块 181 方向门）。
  一般机构只保证这个夹逼，**不保证**相对短缺 ≤ 1 − cos(π/k)。互锁算例在 tanψ·μ·(1+cos(π/k)) + cos(π/k)·μ² < 1 时
  由夹逼可推出该界（条件与结论见 `tests/test_limit_scale.py` 模块说明；那里没写推导，补在这里：令 t = tanψ、c = cos(π/k)，
  下界 tan(ψ + atan(μc)) ≥ c·tan(ψ + φ) 去分母后等价于 (t + μc)(1 − tμ) − c(t + μ)(1 − tμc) ≥ 0，左边恒等于
  t(1 − c)[1 − tμ(1 + c) − cμ²]，条件成立（且 t, μ ≥ 0）时它 ≥ 0，两个分母也都为正），而且两个文件都直接断言了它：
  `test_limit.py::test_three_d_cone_linearisation_is_conservative_within_the_inradius_bound`（15 个 k）与 `test_limit_scale.py::test_patton_sweep_is_optimal_and_inside_the_inscribed_cone_bracket`（50 格，并先断言该条件成立）。
  误差**不随 k 单调**：它取决于滑动方向相对切向基架的夹角——互锁算例的荷载平面恰含一条棱时（k 为 4 的倍数）精确，
  k = 5 反而比 k = 4 差得多。原来的"收敛门"里 k = 6 被 `if k >= 8` 豁免，"收敛"从未被真正检验过（审查 minor 条目）。
- **刚体、小变形、接触位置在加载中不变**——极限分析的标准前提。几何非线性不在内，
  所以大位移下的互锁"爬坡"过程它算不了（那是 L5 逃逸剖面的领域，两者互补）。
- **只做单个动体对固定边界。** 多体机构要把各体自由度并进同一组平衡方程，未实现。
- 本构只有库仑摩擦 + 黏聚力，抗拉一律为零。要接别的本构（DDA 的节理强度、夹具的
  摩擦模型）是在这一层插，内核不动——这正是 L3 的设计意图。
- 关联流动：极限分析的经典框架假定剪胀角 = 摩擦角，这对真实岩石**偏不安全**
  （实测剪胀角通常小于摩擦角）。非关联流动下上下限不再重合，需要别的方法。**必须写明。**

### 一、求解器的三个数值缺陷

问题的根子是同一个：`lp.solve` 的各种阈值是**绝对**的，直接作用在原始数据上，而极限分析的数据量级天然悬殊
（荷载可以是 100 也可以是 1e6，黏聚列 ∝ c·A，几何缩小后力矩行整体变小）。

1. **假不可行。** 一阶段用"人工变量之和 > tol"判不可行，`limit_load` 还把 tol 再乘 1e-3 变成 1e-12；
   N = 100 时一阶段收敛后的舍入残差约 2e-12，于是可行问题返回 `infeasible`、α = nan。
   审查复现出 9 个这样的互锁格子，其中包括默认 k = 8 的 (0.2, 0.1)（真值 52.083）和计划 M0.a 点名的 (0.3, 0.1, k=16)
   （2026-09-24 在 cc5d7cf 的 `limit.py` + `lp.py` 上逐格重跑，9 格全部 `infeasible`；格子清单即 `test_limit_scale.py::AUDITED_CELLS`）。
   同源的另一个：一阶段结束时某列检验数只是 ~1e-12 的舍入噪声，旧代码把这种"一阶段无界"（精确算术里不可能）也报成不可行。
2. **列缩放假不可行。** 把 10 列乘 1e2 或 1e4（变量换元，可行集不变），6 个对照种子里有 4 个（9、18、42、48）被判不可行。
   极限分析里黏聚列与摩擦列差几个数量级是常态，所以这不是纯数学上的担心。
3. **静默错值，最坏的一种。** 三维扁块四角带黏聚（μ = 0.2、各 cA = 1.5·s），荷载 ×1e4、k = 16：
   旧求解器的表格在主元过程中失稳，基解已不满足 Ax = b，却照样报 `optimal`，承载力超出解析上界 μW + 4cA。
   倍数取决于测量配置（2026-09-24 重跑：算例即 `tests/test_lp_fail_loud.py::_cohesive_block(1e4, g)`、k = 16，
   旧代码取自 `git archive cc5d7cf src` 解出的临时目录；残差为 max|Ax − b|）：
   - **M0 前的真实链路**（cc5d7cf 的 `limit.py` + `lp.py`，`limit.py` 把 tol 乘 1e-3 后以 1e-12 传给 LP）：承载力是上界的 **2.12 倍**、残差 5.6e4；
   - 同一真实链路、同一算例改 **k = 5**：报 `optimal`，**承载力为负**（−492664，夹逼 [64721, 80000]）；荷载不放大（s = 1）时正确（7.919 ∈ [6.472, 8]）。2026-09-24 在 `git archive cc5d7cf src` 上实跑。
     几何再 ×1e-3 时 1.04 倍、残差 1.0e4。
   - 旧 `lp.py` 用它自己的默认 tol（1e-10）、接在当前 `limit_load` 后面：1.46 倍、残差 1.7e4；几何 ×1e-3 时 1.02 倍、残差 1.0e3。

   任何只看 status 的调用方都会把这个数当真——对 M0 前的调用方来说是 2.12 倍那个数。

**修法**，三件事，都在 `src/eab/lp.py`：

- **2 的幂精确均衡**：先列后行，把每列、每行的最大元缩到 [0.5, 1)；右端项（已规整为 ≥ 0）仅当 max b > 1 时再按不小于 max b 的 2 的幂归一。
  因子全是 2 的幂，乘除都精确，不引入任何舍入——所以对 max|b| > 1 的问题，b 乘 2 的幂时整个求解逐位按比例（x 逐位乘同一因子、y 逐位不变），
  主元序列不变（`test_lp_scale.py::test_power_of_two_rhs_scaling_is_bitwise_proportional`，先把 b 乘 4 并断言 max|b| > 1）。

### 二、对偶机构不唯一

"破坏模式从对偶解读出来"在二维方块上是干净的，到了三维要收窄：对偶最优解不是一个点，而是一个**最优面**，
返回哪个机构取决于单纯形的选主元顺序。能当结论写的只有这个面上的**不变量**，不是返回机构的逐分量取值。

端到端门里 cb2 上块沿 +x 推（W = 10，k = 8）：

- **滑动（μ < 1）**：推力恰好落在八边形内接锥的一条棱上，切向速度的方向可以在推力两侧 ±π/k（±22.5°）内任取；
  当前实现返回的是纯平动、**偏 −22.5°**（v_y / v_x = −tan(π/8) ≈ −0.4142）。在仓库根目录跑
  `python -X utf8 -c "import sys; sys.path[:0]=['src','tests','tools']; import test_end_to_end_cb2 as T; print(T._capacity(T.CASES[0],0.4,(1.0,0.0))[0].mechanism)"`
  得 `[1.0, -0.414…, 0.4, 0, 0, 0]`。而且最优面里**还有带转动的机构**：μ = 0.4 时 (1, 0, 0.4, 0.117, 0, −0.293)
  （精确值 ω = (μc, 0, −c)，c = 1 − 1/√2）在原问题上同样容许、上限同样等于 α = 4.0（用门里的 `_power` 核算：最差接触功率 0、上限 4.0）。
  所以"往哪个方向滑"和"滑动时有没有转动"**都不是**定义良好的输出。不变的是：沿推力的平动 + 关联剪胀 T = (1, 0, μ, 0, 0, 0) 是最优对偶之一。
- **倾覆（μ > 1）**：绕前缘转动 R = (0, 0, 1, 0, 1, 0) 是最优对偶，而**任何**纯平动的上限都 ≥ μW > α，
  所以返回的机构必须带转动——"带转动"只在倾覆时是真不变量。
- **μ = 1**：T 与 R 并列最优。

机构不唯一不影响承载力：α 本身是唯一的，下一节各格都与闭式吻合到 1e-9；对偶间隙与互补违约，门断言 < 1e-9·max(1, α)
（μ = 0.3、1.5，α = 3、10，即阈值 3e-9、1e-8；`test_end_to_end_cb2.py::test_lower_and_upper_bounds_coincide_end_to_end`），实测对偶间隙 1.8e-15、1.2e-14。

门：`test_end_to_end_cb2.py::test_failure_mode_is_read_off_invariants_of_the_dual_face`（μ = 0.4、0.95、1.0、1.05、2.0），
用一个不调用 `eab.limit.wrench` 的独立刚体虚功率核算（`_power`）断言：返回的机构容许、驱动为 1、上限 = α（它确是最优对偶）；
滑动时 T 的上限 = α；倾覆时 R 的上限 = α、T 的上限 > α 且返回机构的角速度非零；μ = 1 时 T、R 上限都 = α。
它由 8376ec2 引入，取代 b26d7f5 的 `test_failure_mode_is_read_off_the_dual_mechanism`——后者在滑动分支断言"无转动、偏角 ≤ π/k、v_z = μ·v_x"，
断言的是单纯形恰好挑中的那个顶点，不是最优面的不变量（下文第三节的力矩反号变异正好把它挑到了最优面上
ω = (μc, 0, −c)（c = 1 − 1/√2）那族带转动的顶点：μ = 0.4 时 (0.117, 0, −0.293)，μ = 0.95 时 (0.278, 0, −0.293)，于是两例都红了）。
`src/eab/limit.py` 模块文档的诚实条款此前仍把"是否转动"列为读破坏模式的不变量、并指向已删的旧门；094861c 已跟上这一口径
